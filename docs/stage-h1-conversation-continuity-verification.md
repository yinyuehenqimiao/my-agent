# 阶段 H1：对话路由连续性与知识来源展示验证

## 阶段目标

本阶段修复企业助手在知识库展示、工作流临时跳出、当前时间与流程结束后追问四个场景中的连续性问题：

1. RAG 检索分片仅用于生成答案，聊天侧按文档聚合展示来源摘要，不暴露片段正文和内部 `chunkId`。
2. 请假流程收集参数期间，制度问题走 RAG、余额问题走 ReAct；临时查询不覆盖持久化工作流状态，用户随后提供请假理由时继续原流程。
3. 当前日期时间由服务端使用 `Asia/Shanghai` 时区的系统时钟生成，不交给模型猜测。
4. 工作流进入非活动状态后，在会话 TTL 内保留最近业务上下文，使“能修改吗”能关联刚才的请假流程。

## 关键验收场景

### 场景一：知识来源摘要

- 输入：`公司的请假制度是什么`
- 预期：回答正文是检索增强后的自然语言答案。
- 预期：工具摘要显示“已参考 N 份文档”及文档名。
- 预期：SSE 与持久化消息块不包含 `excerpt`、`chunkId` 或完整分片正文。

### 场景二：工作流中途查询并恢复

1. 输入：`请假26年9月20日-22日`
2. 助手询问请假理由。
3. 输入：`公司的请假制度是什么`
4. 预期：本轮路由提示为知识库/RAG，并回答制度；工作流状态仍处于参数收集。
5. 输入：`我的年假还有多少`
6. 预期：本轮路由提示为 ReAct，并调用个人年假余额工具；工作流状态仍保留。
7. 输入：`我请假的理由是旅游`
8. 预期：恢复请假固定流程并继续确认/提交，不要求重新描述业务对象。

### 场景三：当前时间

- 输入：`当前时间是什么时候`
- 预期：返回服务端实时北京时间，格式包含日期、星期、时分秒与“北京时间”。

### 场景四：完成后的省略式追问

1. 完成一笔请假流程。
2. 紧接着输入：`能修改吗`
3. 预期：关联最近请假上下文，说明不能直接修改以及“查看申请、允许时撤回、重新提交”的处理路径。

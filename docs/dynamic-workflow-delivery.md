# 动态业务工作流交付说明

## 部署顺序

1. 备份 PostgreSQL，并按版本顺序执行 `resources/database/upgrades/v0.9.0` 下脚本。
2. 配置平台权限：`workflow:view`、`workflow:edit`、`workflow:review`、`workflow:publish`、`workflow:run`、`audit:view`。
3. 配置 MCP 连接器的地址允许范围和服务端凭证引用；凭证值不得保存到数据库或流程 JSON。
4. 启动 ERP、PostgreSQL、Redis、RocketMQ、后端和前端；先执行只读工具和知识问答冒烟测试。
5. 管理员通过业务积木创建草稿，依次执行校验、模拟、提交审核、独立审核和发布。
6. 写工具开放前，验证确认卡、幂等键和 ERP 单据结果查询能力。

## 灰度策略

- 第一批只发布制度查询和个人信息查询流程。
- 第二批开放带用户确认的 ERP 写流程；旧 `leave-approval` 继续处理历史与在途实例。
- 新实例读取 `current_published_version_id`，在途实例固定使用启动版本。
- 连接器或工具可紧急停用；Tool Gateway 每次调用都会重新检查启用和权限状态。

## 回滚

- 工作流回滚只切换定义的当前发布版本，不修改 Flowable 在途实例。
- 前端故障时可回退前端资源，后端发布版本与运行实例不受影响。
- 动态流程异常时停用对应工具或退休版本，并把新实例入口切回上一已发布版本。
- ERP 仍是单据与审批状态权威来源；平台状态与 ERP 不一致时停止重试并进入结果待核实。

## 故障处理

- `RESULT_UNCERTAIN`：先按幂等键或业务引用查询 ERP，禁止直接重复提交。
- `AUDIT_UNAVAILABLE`：写操作保持拒绝，恢复审计存储后再由用户重新确认。
- 等待任务无法恢复：核对 `wf_wait_state` 与 Flowable 活动任务，不手工修改业务结果。
- 发布失败：检查模拟摘要、审核摘要、依赖契约版本和工具启用状态。

## 已知边界

- 首版不支持并行汇合、任意循环、子流程和在途实例迁移。
- ReAct 只允许已启用的只读工具，最大 5 轮、8 次调用、60 秒。
- 旧 BPMN 只保留兼容运行；新流程以 `process_json` 为唯一编辑源。
- H2 只用于单元测试，正式验收数据库为 PostgreSQL。

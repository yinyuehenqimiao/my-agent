# 阶段 D3：生产路由绑定管理闭环验证

## 阶段目标

让管理员通过中文后台配置“业务意图 → 固定工作流/ReAct”生产管线，并确保后台模拟与真实聊天使用同一套路由逻辑。路由配置必须受租户、权限、发布状态和运行时能力约束。

## 本阶段实现

- 新增路由绑定查询、选项查询、保存和删除接口。
- `route:view` 与 `route:edit` 分权；编辑权限只授予平台管理员和工作流审核者。
- 租户从服务端登录身份读取，列表、选项、保存、更新、删除和运行时查询均按租户隔离。
- 每个租户的路由键唯一，每个租户的业务意图只能绑定一条生产管线。
- 固定流程只允许绑定当前租户已发布、且已有专用运行时工具集的工作流。
- ReAct 当前只允许选择内置 `default` 配置，禁止通过后台注入任意配置文本。
- 只有启用的末级 `WORKFLOW`/`MCP` 意图可以分别绑定固定流程/ReAct。
- 新增、修改、删除分别写入 `ROUTE_CREATE`、`ROUTE_UPDATE`、`ROUTE_DELETE` 平台审计。
- 后台模拟改为复用 `ChatRoutePlanner`，消除模拟结果与真实聊天选取候选意图方式不一致的问题。
- 新增“请假申请”工作流意图种子；不自动创建生产路由，管理员需在流程发布后显式启用。
- 前端提供中文下拉选项、现有绑定列表、编辑、删除确认及真实身份模拟。

## 权限矩阵

| 角色 | 查看路由 | 修改路由 | 路由模拟 |
| --- | --- | --- | --- |
| 平台管理员 | 是 | 是 | 是 |
| 工作流编辑者 | 是 | 否 | 是 |
| 工作流审核者 | 是 | 是 | 是 |
| 安全管理员 | 是 | 否 | 是 |
| 审计员 | 是 | 否 | 是 |

工作流编辑者不能直接切换生产流量；审核者在流程审核发布职责之外承担生产绑定变更职责，所有变更均留审计记录。

## 测试流程与结果

### 红灯复现

1. 先新增 `RouteBindingServiceTest`，测试编译因服务不存在失败，确认项目当时没有任何路由管理能力。
2. 增加非默认租户运行时测试，用于锁定原先硬编码 `default` 租户的问题。
3. 前端接入配置区后的首次测试发现页面选项与模拟结果同名导致断言歧义，修正为验证模拟区域存在对应结果。

## 操作顺序

1. 在“工作流定义”创建流程版本并完成审核、发布。
2. 确认该流程已有专用运行时工具集；未接入的流程不会出现在可选目标中。
3. 在“执行管线与路由模拟”选择业务意图、执行方式和目标，保存生产管线。
4. 使用同页真实身份模拟确认意图、置信度、最终决策和执行目标。
5. 在平台操作审计中核对路由变更记录，再进行真实用户验收。

## 已知非阻断项

- 当前专用固定流程运行时只支持 `leave-approval`；新增固定流程必须先接入最小工具集。
- 当前仅有一个内置 ReAct 配置；后续需要配置模板版本化、审批和灰度能力后再开放更多选项。
- Vite 主包和表格预览包仍有大体积警告，列入后续前端性能阶段。
- Maven 在 Windows 控制台仍有中文日志乱码及本地仓库元数据写入警告，但未影响本阶段构建和测试通过。
